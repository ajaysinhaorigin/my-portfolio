## Introduction

Today, almost every website uses HTTPS.

HTTPS encrypts communication between the client and the server.

Before sending any sensitive data, both sides first create a secure connection.

This process is called the **TLS Handshake**.

<Callout type="definition">
  **TLS (Transport Layer Security)** is the protocol that encrypts data between a browser and a server. HTTPS is HTTP running over TLS.
</Callout>

## Why Do We Need TLS?

Without encryption, anyone on the network path could:

- Read passwords, cookies, or personal data
- Modify responses before they reach you
- Impersonate a website

TLS protects confidentiality and helps verify you are talking to the real server.

## When Does It Happen?

Typical order:

1. DNS finds the IP.
2. TCP three-way handshake opens a connection.
3. **TLS handshake** secures that connection.
4. HTTP request/response rides on the encrypted channel.

## During the TLS Handshake

At a high level:

- The server sends its SSL/TLS certificate.
- The browser checks whether the certificate is trusted.
- Both sides agree on encryption keys.
- A secure connection is created.

After this, all communication becomes encrypted.

## Certificates and Keys

The certificate proves the server's identity for a domain (for example, `www.google.com`).

It is tied to a **public key**. The matching **private key** stays on the server.

<Callout type="remember">
  The server's **private key never leaves the server**. Only the certificate and public key are shared.
</Callout>

If the certificate is expired, mismatched, or untrusted, the browser shows a warning.

## HTTP vs HTTPS

| | HTTP | HTTPS |
|---|------|-------|
| Encryption | No | Yes (via TLS) |
| Default port | 80 | 443 |
| URL starts with | `http://` | `https://` |
| Safe for passwords | No | Yes |

HTTPS is not a completely different language for pages — it is HTTP protected by TLS.

## Key Takeaways

- TLS creates a secure channel on top of TCP.
- The handshake exchanges certificates and agrees on keys.
- The private key never leaves the server.
- HTTPS = HTTP + TLS.
- After TLS succeeds, HTTP requests and responses are encrypted.
